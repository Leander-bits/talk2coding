# 项目目标与约束

更新于 2026-11-22。首版 CLI 已接入按键录音、Whisper 和 DeepSeek 请求。真实设备、模型和付费 API 的验收进度见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 已确认事实

- 工作名称沿用仓库名 **talk2coding**：把口述开发需求整理为编码 AI 可以使用的 prompt。
- 目标用户是 vibe coding 用户、开发人员，首先满足个人使用。
- 核心问题是口述可能包含赘述、重复、跳跃和不清楚的表达；需要理解、提取、重构和总结，而不只是逐字转写。
- 运行位置是 Windows 上 VS Code 的 PowerShell 集成终端；生成的 prompt 显示在终端，由用户复制到右侧 Codex。
- 第一版必须完成整体架构设计、开源语音识别模型选型，以及类似游戏的按住说话控制，避免启动后一直接收并转写声音。
- 按住录音键时显示本地实时转写预览，松开后显示本段完整转写。可以继续按住补充，最后在终端按 Enter 统一生成 prompt。
- 内容整理使用 DeepSeek 官方当前的 DeepSeek-V4.1-Flash 服务，官方 API 模型标识为 `deepseek-flash`。[官方说明](https://api-docs.deepseek.com/quick_start)
- 首版采用单文件 Python CLI，`sounddevice` 录音、`faster-whisper` 转写，使用 OpenAI Python SDK 通过配置的 HTTPS API 根地址请求 DeepSeek。

## 第一版范围

完整运行命令和验证状态见 [DEVELOPMENT.md](DEVELOPMENT.md)。

1. 启动后检查配置，加载本地 ASR 模型，显示麦克风、录音键和操作提示，进入未录音的待命状态。
2. 按住可配置键才打开音频采集。终端显示“录音中”后开始说话，录音期间更新最近语音的实时预览。松开后先停止采集，再转写完整录音。
3. E 替换当前草稿的最后一段。Enter 提交当前完整草稿，R 重新发送最近一次提交的转写。C 清空草稿和可重新提交的转写。
4. 本地 ASR 首选 Whisper large-v3-turbo，运行引擎为 faster-whisper。第一批样本覆盖普通话和英文技术词，识别效果待验证。
5. DeepSeek 只处理本次确认的转写文本及固定整理指令；去掉口头赘述、合并重复、梳理顺序，保留目标、限制、否定和明确修正。
6. 输出中文 Markdown prompt，依次使用 `# 目标`、`# 背景`、`# 需求`三个一级标题。限制写在对应需求下，有歧义或缺少关键信息时，在对应小节写「待确认」并说明需要确认什么。
7. 终端状态信息与最终 prompt 分区。最终内容使用明确开始/结束标记，不掺入日志，供用户直接选择复制；一次完成后可开始新会话。

第一版暂不纳入：VS Code 插件、图形界面、自动操作 Codex、自动提交代码、自动执行生成的命令、自动读仓库补充上下文、唤醒词、后台常驻录音、云端 ASR、账户系统、数据库和跨设备同步。剪贴板自动写入也不作为首版必需项。

## 约束与数据边界提议

| 项目 | 提议与状态 |
| --- | --- |
| 实现方式 | Windows x64 上的 Python 3.13 单文件 CLI，使用项目虚拟环境 |
| 录音控制 | 程序运行期间查询全局录音键状态。会话命令只在终端中接收 |
| 待命与停止 | 待命、松开后处理整段、生成 prompt 期间不采集麦克风。录音键释放、取消、异常和退出均停止采集 |
| 数据流 | 本地采集音频并转写。Enter 发送草稿，R 发送最近一次提交的转写，均附固定整理指令 |
| 保存策略 | 当前音频、草稿和最近一次提交保存在内存。C 清空草稿和最近提交，退出时释放内存。终端可能保留滚动记录，模型权重缓存单独管理 |
| 凭证 | 仅通过环境变量等本地安全配置提供，不写入仓库或日志；不要求用户在对话中提供密钥 |
| 外部调用 | 本次没有实际调用授权；后续真实付费联调另按明确目标、次数/预算和测试文字范围授权 |
| 性能 | 不以官方基准代替本机结果；先测加载、转写和生成耗时，再确定可承诺指标 |

## 可检查的验收条件

以下是首版验收条件。最近验证见 [快捷键、标点和提示词任务](tasks/2026-11-22-punctuation-and-repeat.md)、[实时转写任务](tasks/2026-11-22-live-transcript.md)和[录音与 DeepSeek 功能任务](tasks/2026-11-22-record-and-generate.md)。[骨架阶段验收](tasks/2026-11-22-scaffold-acceptance-audit.md#逐条核对)为历史记录。

| 编号 | 场景与检查方法 | 通过条件 |
| --- | --- | --- |
| A1 | 阅读架构和选型记录 | 可定位入口、模块职责、依赖方向、录音状态机、数据边界、失败处理、模型依据与替代方案；提议与现状明确区分 |
| A2 | 在 VS Code PowerShell 启动并连续待命 30 秒，旁边播放声音 | 无音频帧进入会话缓冲，无转写任务、无模型 API 请求；麦克风采集流未启动 |
| A3 | 连续按住、松开录音键 10 次，包含长按重复事件和一段持续约 10 秒的讲话 | 持续讲话时松键前可见并更新实时预览。每次只开始一段，松开即停止采集，最终整段包含首尾词，预览不会造成重复段 |
| A4 | 在终端、编辑器、Codex 面板间切换焦点进行按住/松开 | 录音键在普通桌面会话有效，松开不因焦点变化丢失；Enter 等命令不在其他面板触发；不要求管理员运行，不静默改 VS Code 快捷键 |
| A5 | 麦克风列表、指定设备及默认设备测试 | 使用用户选定的输入设备；无设备、权限拒绝、采样率不支持、设备断开时给出可操作错误并释放资源 |
| A6 | 短按、纯静音、噪声、超过录音上限 | 空/无有效语音段不进入生成；达到建议单段 120 秒上限时停止并提示分段补充，不静默截断；误判可重录 |
| A7 | 用至少 10 段经同意的本人口述样本验证 ASR | 覆盖普通话、英文技术词、数字、否定、口头修正和噪声；预先标注关键事实，建议至少 90% 样本未经修正即保留全部关键事实；逐项记录错误，提交前可修正。该门槛为待样本基线确认的草案，不代表已测准确率 |
| A8 | 录制两段、修正末段并按 Enter，随后按 R | Enter 仅发送当前两段，R 仅发送最近提交的同一份文字并保留新草稿。长按 R 不重复发送，C 清空草稿和最近提交 |
| A9 | 用固定转写验证整理质量 | 至少覆盖赘述、重复、明确改口、冲突、信息不足五类；明确事实与限制全部保留，无擅自新增功能/技术栈；未消解冲突列为待确认 |
| A10 | 查看生成内容并复制到 Codex 输入框 | 标题层级和顺序符合固定格式，中文可读，正文无日志或推理内容，供用户手动复制 |
| A11 | 模拟缺密钥、鉴权失败、限流、超时、空响应和输出截断 | 不报告成功，不静默换模型；当前转写保留供修正或主动重试；每次提交最多一个在途请求，无无限重试 |
| A12 | 模拟队列溢出、忙碌时按键、取消、Ctrl+C 和异常退出 | 溢出可见且重录，忙碌时的操作不触发后续录音或请求。退出时停止采集和键状态查询，按保存策略清理会话数据 |
| A13 | 联调前后检查网络、文件及日志 | 音频不上传、不默认落盘；只发送当前提交文字与固定指令；日志无密钥、完整录音或默认保存的完整转写 |
| A14 | 模型预热后对同一组 10/30/60 秒录音计时 | 记录模型/权重版本、推理设备、精度、耗时和峰值内存/显存；建议 GPU 转写耗时不超过录音时长，正式性能门槛待基线确认 |
