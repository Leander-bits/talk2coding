# 分步提示词

按顺序发送前五步；已有项目可直接使用后面的迭代提示词。方括号内容在对话中替换，也可以直接补充自己的描述，不需要编辑 Markdown。每一步完成后检查结果，再继续。

AI 默认维护受影响的文档：项目目标 → `PROJECT.md`，命令与验证 → `DEVELOPMENT.md`，结构与决策 → `ARCHITECTURE.md`，复杂任务 → `docs/tasks/`。README 中英文只保留介绍、结构和必要链接，不需要每次改写所有文件。

## 第 1 步：明确需求，填写项目文档

```text
请读取 AGENTS.md、docs/PROJECT.md 和 docs/DEVELOPMENT.md，检查当前仓库。
我要开发：[用自己的话描述项目]。
目标用户：[谁使用]。第一版必须完成：[核心流程]。本次不做：[排除项]。
已有偏好或限制：[平台、语言、预算等；不确定可留空]。
请提炼可检查的验收条件，由你填写项目文档，不要要求我手动编辑文件。
区分已确认事实、提议和未知项；只对影响实现或授权的关键问题提问。
复杂任务按 TASK_TEMPLATE.md 建任务记录，小任务不额外建文件。
这一步先确认需求，不写业务代码。
```

## 第 2 步：选择技术方案和代码结构

```text
请基于已确认需求给出一个最简单可维护的推荐方案，说明必要依赖及替代选择。
说明入口、主要流程函数、输入输出、可复用功能，以及外部服务和数据边界。
Python 简单项目优先一个 .py，复杂项目按职责分文件；说明选择理由。
遵守禁止嵌套函数、main() 主入口和按需使用 class/抽象类的规则。
将提议记录到 docs/ARCHITECTURE.md，等待我确认；暂不安装依赖或实现。
```

## 第 3 步：确认方案，建立可运行骨架

```text
采用你上一条推荐的方案，授权安装该方案明确列出的必要项目本地依赖。
建立最小可运行骨架和适用的检查配置，遵循仓库的入口与代码组织规则。
运行实际命令，把环境、依赖、启动及检查方式写入 docs/DEVELOPMENT.md。
更新结构与已确认决策，并将 README 中英文改为本项目的简洁介绍和结构，保留语言切换。
新增方案外的运行时依赖、高影响操作或外部写入时，再按规则确认。
```

## 第 4 步：完成最小功能

```text
请按已确认的需求和验收条件，完成最小可用版本。
按业务步骤组织流程函数，共用逻辑提取为独立辅助函数，不定义嵌套函数。
覆盖输入校验、正常流程和必要失败处理，避免无关功能和提前抽象。
外部服务尚未配置时使用明确标注的模拟实现，并说明真实集成尚未完成。
增加必要测试、运行相关检查，主动更新受影响文档和任务进度。
授权范围是本地实现与测试，不包括真实付费调用、发送、发布或生产写入。
```

## 第 5 步：测试、审查和验收

```text
请逐条核对验收条件，运行适用的测试、静态检查和构建；有界面时检查真实页面。
审查正常、边界、失败路径，以及数据与权限、兼容性和重复操作风险。
检查代码是否便于人类/AI 审查，入口明确，没有嵌套函数，拆文件符合实际复杂度。
修复有证据的问题，不降低检查标准，不引入无关重构。
更新文档和任务记录，报告已通过、失败、未验证项及原因，不将模拟成功当成真实集成成功。
```

## 可选：接入真实服务

```text
请把[模拟功能]接入[服务名称及连接方式]。
先核对官方文档和必要依赖，再实现适配与错误处理，保留可隔离测试的模拟方式。
由你创建无秘密的 .env.example 和配置说明，不要求我把密钥粘贴到对话里。
说明安全配置所需的账号操作；文档和代码由你维护。
本次授权实现集成和隔离测试；真实调用费用、发送或生产写入另行明确授权。
```

## 可选：限定范围的真实验证

```text
本地凭证已安全配置，请勿打印或读取展示其内容。
我授权这一次真实验证：动作[具体动作]，目标[准确目标]，环境[测试环境]。
允许的输入和数据范围：[范围]。次数或费用上限：[上限]。
先检查执行条件，在授权范围内验证并报告实际结果。
结果不确定时停止，不擅自重试或扩大目标，更新验证记录。
```

## 测试后：修改细节

```text
我试用后希望调整：[描述细节或附上现象]。
目前表现：[现在怎样]。期望表现：[希望怎样]。
必须保留：[不能改变的行为]。
请做最小改动，验证该调整及受影响的原功能，更新相关文档和必要测试。
```

## 测试后：修复缺陷

```text
出现问题：[错误现象与脱敏报错]。
复现步骤：[操作或输入]。预期结果：[结果]。实际结果：[结果]。
请先查明原因，条件允许时先增加能复现问题的失败测试，再修复并验证。
不要靠猜改、删除有效测试或放宽检查处理；更新验证记录和受影响文档。
```

## 后续：增加新需求

```text
在现有项目增加：[新需求]。验收条件：[可检查的行为]。
本次不做：[排除项]。保持兼容：[原有功能或接口]。
先检查影响范围和现有结构，补充项目文档；复杂任务建立独立任务记录。
低风险改动直接完成并验证，新增依赖或高影响操作按规则确认。
```

## 后续：代码整理

```text
请整理[文件或模块]，保持对外行为不变。
目标是流程清楚、代码精简、便于审查，去除重复和不必要的层次。
不要定义嵌套函数；简单项目保留单文件，已复杂的项目按职责拆文件并说明原因。
先检查现有行为和测试，再作最小整理，验证行为未变并更新结构文档。
```

## 后续：更换会话继续

```text
请读取仓库规则、项目文档及当前任务记录，复核仓库状态后说明已完成项和下一步。
按原任务继续已授权的独立工作；需要新授权时说明具体动作和目标。
信息不完整时不要假设过去的聊天内容，由你维护后续进度和文档。
```

## 后续：修改通用规则

```text
请将这项约定加入通用规则：[具体约定]。
检查与现有规则是否矛盾，只修改本次要求涉及的规则与说明。
由你更新 AGENTS.md，执行同步脚本及 --check，确保 Copilot 副本一致。
如影响项目文档或提示词，一并更新；不要要求我手动同步文件。
```

上传或部署是独立动作。需要 AI 执行时，用对话明确仓库、分支或环境及允许的操作；上传流程见 [GITHUB.md](GITHUB.md)。
